# Сверка с требованиями Codex Challenge

Проверка от 16 ноября 2026 года для IT Lab 3D 1.4.0. Источник — предоставленный участником файл «ПОЛОЖЕНИЕ КОДЕКС ЧЕЛЕНДЖ.docx»: версия 1.7 от 13 ноября 2026 года, приложение 2 к приказу и пункты положения, указанные ниже. Это сверка материалов, а не оценка жюри. Возможные последующие официальные изменения здесь не подтверждены.

## Материалы проекта

| Требование | Что подготовлено | Результат сверки |

Хостинг Sites сейчас ограничен владельцем. Его нельзя использовать как единственную ссылку для рецензента. Для проверки подготовлен публичный репозиторий с автономным запуском; права доступа к хостингу не менялись.

## Пять критериев оценки, п. 8.6

| Критерий | Подтверждение / ограничение |
| --- | --- |
| Ясность проблемы и цели | В паспорте указан начинающий студент колледжа и задача: восстановить запуск ПК после диагностики памяти |
| Работоспособность основной функции | Есть полный сценарий, успешная повторная проверка и журнал действий |
| Качество результата | Результат проверяется по установленной RAM, загрузке системы и принятому завершению практики; это не сертификация знаний студента |
| Практическая польза | Повторяемая практика без разборки реального ПК описана. **Экономия времени, качество усвоения и результаты реальных студентов ещё не измерены**; максимальный балл по этому пункту не подтверждён |
| Применение в других организациях | Нет привязки к колледжу или данным студентов; описаны запуск, редактирование материалов, зависимости и проверка преподавателем |

48 автоматических тестов подтверждают поведение программы. Они не доказывают улучшение успеваемости или экономию учебного времени.

## Что ещё относится к участнику и официальной подаче

1. Заполнить Ф. И. О. в паспорте. Учебное заведение ранее также было решено не указывать; если форма запрашивает его отдельно, заполнить там.
2. Проверить условия допуска: индивидуальное участие, возраст от 18 лет и работа в образовательной организации Казахстана, пп. 3.1–3.3. Эти сведения не проверялись.
3. Подать ссылки через официальную систему. Публикация в GitHub сама по себе не является конкурсной подачей, п. 6.1.
4. Выполнить обязательные учебные задания, участие в сессиях и последующее рецензирование трёх назначенных проектов. Автоматически созданные материалы этого не подтверждают.
5. Отдельно предоставить действительные доказательства распространения опыта по п. 8.7. Видеообзор продукта не заменяет доказательства проведённого семинара или другого мероприятия.

По предоставленной версии: MVP — 12–16 ноября, итоговый пакет — 18–20 ноября, рецензии — до 2 декабря, доказательства распространения — до 4 декабря 2026 года. Организатор может менять сроки официальным сообщением; здесь приведены даты именно из полученного файла.

Для финалистов предусмотрен отдельный формат: пять минут демонстрации и пять минут вопросов, п. 9.3. Он не заменяет лимит короткого видео итогового пакета.
