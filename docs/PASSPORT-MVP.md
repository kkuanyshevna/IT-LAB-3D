и задание для тестирования MVP

## 1 Какую проблему решает проект

Студенту недостаточно запомнить названия деталей: нужно узнать их на плате и связать с работой системы. Цель проекта - дать стенд для изучения компонентов и проверки диагностических гипотез. Пользователь нажимает на деталь, читает объяснение и выполняет действия с наблюдаемым результатом. Полезный результат - правильно восстановленный учебный ПК и понятная последовательность проверок.

## 2 Как пользоваться проектом

1. Открыть репозиторий по ссылке ниже, выбрать Code, затем Download ZIP и распаковать архив.
2. Открыть index.html из распакованной папки и дождаться отметки «3D готово».
3. В «Исследовать» нажать на узел; через «Плата изнутри» рассмотреть мелкие компоненты.
4. Выбрать учебный режим, выполнить действия, проверить результат и при необходимости скачать TXT-отчёт.

Основной доступ для рецензента: https://github.com/kkuanyshevna/IT-LAB-3D

## 3 Как протестировать проект за 3-5 минут

Тестовое задание: восстановить изображение после диагностики отсутствующей оперативной памяти.

Исходные данные: режим «Неисправности», случай «Вентиляторы вращаются, но экран остаётся чёрным». ПК включён, боковая панель закрыта, RAM отсутствует. Дополнительные файлы и личные данные не нужны.

1. Открыть «Неисправности» и выбрать указанный случай. Зафиксировать исходный симптом на учебном экране.
2. В «Действия с ПК» выключить ПК и снять панель. В «Проверки» нажать «Память»: отсутствие RAM должно быть обнаружено.
3. Восстановить RAM: перетащить модуль в DIMM или выбрать RAM и DIMM в форме установки.
4. Вернуть панель, включить ПК, нажать «Экран» в проверках и «Завершить проверку».

Ожидаемый результат: RAM установлена в 3D; появляется экран готовой системы; диагностика завершается. Признаки качества: журнал содержит исходное обнаружение дефекта и успешную повторную проверку. Попытка завершить без этих наблюдений не засчитывается.

## 4 Какова практическая эффективность

Стенд позволяет повторять один сценарий без изменения реального оборудования и сохранять журнал действий для разбора. Реализованы 12 крупных узлов, 24 типа компонентов платы и три диагностических случая. Разработчиком выполнены 48 автоматических тестов и браузерные проверки основных действий. Экономия времени и образовательный эффект с реальными студентами ещё не измерялись; проценты улучшения не заявляются.

## 5 Как использовать в другой организации

Преподаватель другого колледжа может скачать проект и открыть тот же index.html на учебном ПК. Личные учётные данные, данные студентов и привязка к конкретному колледжу не требуются. Для изменения объяснений редактируется component-lessons.js, для новых случаев - учебная логика сценариев. После изменения исходников нужна пересборка через npm run build; Node.js 24 - проверенная версия среды. Three.js и OrbitControls используются с сохранёнными лицензионными уведомлениями; сторонние фотографии и готовые 3D-модели не используются. Содержание и результаты практики проверяет преподаватель профильной дисциплины. Живой ИИ для проверки MVP не нужен: сейчас доступны подписанные подсказки по правилам, а серверное подключение модели подготовлено для будущего API-ключа. Предоставленный короткий сценарий можно использовать без доработок.
